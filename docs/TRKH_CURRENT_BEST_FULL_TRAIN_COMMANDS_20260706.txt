WHY THESE COMMANDS ARE SAFE TO PASTE IN VS CODE

- Every command is one physical line and uses an absolute script path.
- The wrappers set the repository working directory themselves.
- Native Python processes are invoked directly. They are never piped through
  `2>&1 | ForEach-Object`, which caused the NativeCommandError in the supplied
  VS Code screenshot when Python wrote valid INFO logs to stderr.
- Every native process is checked with `$LASTEXITCODE`; a failed step stops the
  next step and writes pipeline_status.json.
- Training always uses -SkipFinalTest internally. The explicit -RunFinalTest
  phase opens test only after training, architecture trace, all validation
  audits, and the raw validation promotion gate pass. The gate requires both
  independent-reload macro F1 >= 0.882925 and class-1 F1 >= 0.678261. This
  compares the new checkpoint with the keeper through the same evaluator;
  0.884675/0.686047 remains the in-training anchor, not the reload gate.

1) OPTIONAL PREFLIGHT ONLY (no train, no test, no run directory)

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\DataAI\AIEx\TRKH\scripts\run_trkh_current_best_full_pipeline.ps1" -RunName "preflight_current_best_$(Get-Date -Format yyyyMMdd_HHmmss)" -RunFinalTest -PreflightOnly

2) ONE-COMMAND FULL PIPELINE: TRAIN + VALIDATION AUDITS + FINAL TEST + XAI

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\DataAI\AIEx\TRKH\scripts\run_trkh_current_best_full_pipeline.ps1" -RunName "full_v8_yolof_current_best_30e_$(Get-Date -Format yyyyMMdd_HHmmss)" -RunFinalTest

The one command above runs, in order:

- exact current selected TRKH v8 recipe, max 30 epochs, patience 3, architecture trace;
- independent full validation for raw checkpoint and frozen softboost001 hook;
- validation prediction forensics, class-confusion audits, and boundary reviews;
- full validation robustness audit;
- raw and verifier-aware validation XAI with robustness probes and transition summaries;
- a validation promotion gate against the selected raw keeper;
- raw and verifier-aware locked final-test evaluation only when that gate passes;
- final-test prediction forensics, confusion audits, verifier-aware boundary review;
- verifier-aware final-test XAI and transition summary;
- final artifact-retention audit;
- runs\latest_full_pipeline.json, which points export/video wrappers to the completed run.

If the gate fails, the same command still preserves all validation audits,
writes status `validation_gate_rejected`, skips test, and does not update the
latest deploy pointer. Do not use final-test outputs to alter thresholds,
losses, or model selection; test remains a final report only.
