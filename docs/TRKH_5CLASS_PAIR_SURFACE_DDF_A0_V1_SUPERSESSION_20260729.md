# Pair-Surface DDF A0 v1 supersession — 2026-07-29

## Decision

The 2026-07-25 Pair-Surface DDF A0 fold lock is superseded before formal
execution. It must not authorize an OOF information claim, replay,
keeper-integration smoke, probe, full train, or test. The original protocol,
lock, engine and synthetic engineering evidence remain immutable historical
artifacts.

No formal or replay authorization was consumed. This decision was made without
formal-cohort candidate scores, new validation/test access, pixel decoding, or
GPU execution. Synthetic engineering traces existed, and the project test had
already been opened historically; neither was used by this supersession audit.

## Why exact-stem disjointness was insufficient

The locked folds have zero exact-source-stem overlap, but the cohort comes from
a dataset whose manifest already defines a stronger near-duplicate/family
relation named `leakage_group`. A metadata-only casefold-exact join covers all
763 cohort rows and shows:

- 150 of 531 manifest groups span multiple folds;
- those groups cover 330 rows and create 217 cross-fold row pairs;
- 92 pairs have the same label and 125 have different labels;
- 105 of the 150 split groups contain more than one label.

This grouping was generated by clean CVAT exporter commit
`0c7fd8b873d34d18c6f6f6588b772996528ba0ec` from normalized source families
plus dHash/colour-thumbnail near-visual unions. The exporter file SHA-256 is
`65e6056dac1793eaa9775b458a448828bfd0debd7adc4d9acb58807b7b74e4b5`.
Exact group IDs depend on absolute source paths, so the frozen manifest bytes,
not relocation-based regeneration of the ID strings, are canonical.

Numeric filename proximity independently exposes the same problem. It is a
conservative acquisition-neighborhood proxy, not a verified fruit/session ID:

| Image-number window | Cross-fold row pairs | Covered rows | Same-label | Cross-label |
|---:|---:|---:|---:|---:|
| 1 | 393 | 541 | 316 | 77 |
| 3 | 974 | 659 | 748 | 226 |

The transitive union of casefold-exact stem, manifest `leakage_group`, and
`Image_N` adjacency with gap at most 3 produces 158 components. Under the v1
folds, 85 components cross folds and cover 679/763 rows. Consequently, v1 OOF
metrics could be inflated by correlated capture/family information.

## V2 minimum boundary

V2 must be prospectively committed before any candidate score. Its grouping
unit is the transitive union of:

1. casefold-exact source stem;
2. exact YOLO-manifest `leakage_group`;
3. connected `Image_N` neighborhoods containing every row pair with absolute
   numeric gap `<=3`;
4. trustworthy fruit/session identity if acquisition metadata is recovered.

All rows in one component must stay in one fold. The old `folds` array is
lineage only and the v2 runner must fail if it is accidentally used. Required
cross-fold counts are zero for components, manifest groups, and numeric windows
1 and 3. Candidate scores, keeper metrics, validation or test cannot select the
mapping.
