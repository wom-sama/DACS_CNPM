# TRKH 5-Class Precision Ensemble Readiness Protocol - 2026-07-14

## Status and scope

This protocol evaluates whether the completed scratch run
`full_v8_yolof_randominit_30e_20260714_105524` supplies a complementary signal
to the selected TRKH keeper. It does not edit the dataset and it does not use
test data for fitting, selection, or threshold choice.

An exploratory validation-only calculation preceded this document and found a
stable precision/recall tradeoff worth formalizing. This document therefore
does not claim that the search family was prospectively registered. The test
split remains unopened for the new ensemble rule until every formal gate below
passes. Existing raw test artifacts generated by the user's earlier full run
are not read by the readiness tool.

## Primary references

- Lakshminarayanan, Pritzel, and Blundell, *Simple and Scalable Predictive
  Uncertainty Estimation using Deep Ensembles*, NeurIPS 2017:
  https://papers.nips.cc/paper/2017/hash/9ef2ed4b7fd2c810847ffa5fa85bce38-Abstract.html
- Guo et al., *On Calibration of Modern Neural Networks*, ICML 2017:
  https://proceedings.mlr.press/v70/guo17a.html
- Geifman and El-Yaniv, *Selective Classification for Deep Neural Networks*,
  NeurIPS 2017:
  https://proceedings.neurips.cc/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html

The TRKH rule is deliberately narrower than these papers. It averages two
independently trained same-family probability vectors, then requires class 1
to exceed the strongest non-class-1 probability by a nonnegative margin. It is
a precision-oriented decision rule, not a claim of calibrated posterior
probabilities or a formal selective-risk guarantee.

## Search and fold selection

- Candidate probability weight: `0.00..1.00`, step `0.05`
- Keeper weight: `1 - candidate_weight`
- Class-1 decision-margin offset: `0.000..0.100`, step `0.002`
- Fit-fold class-1 precision floor: `0.65`
- Fit-fold macro-F1 tolerance relative to keeper: `0.002`
- Fit-fold class-1 F1 must not be below the same-fold keeper
- Rank feasible settings by:
  `macro_f1 + class1_f1 + 0.10 * class1_precision`
- Deterministic ties prefer higher macro F1, class-1 F1, precision, then lower
  candidate weight and lower margin offset.

Each fold-selected setting is applied only to its held-out source groups. The
deployable validation setting is locked as the median of the five fold winners,
snapped to the declared grids. No full-validation oracle setting is used.

## Readiness gates

All gates must pass before the locked setting may be applied once to final test:

1. Exact expected validation support and zero source-group overlap.
2. Fold winner range at most `0.10` for candidate weight and `0.02` for margin.
3. OOF macro F1 and class-1 F1 are not below the keeper.
4. OOF class-1 precision is at least `0.65` and at least keeper precision + `0.03`.
5. Minimum held-out fold class-1 precision is at least `0.60`.
6. Median-locked full-validation macro F1 and class-1 F1 are not below keeper.
7. Median-locked precision is at least `0.65`; recall is at least `0.70`.
8. Locked corrections are not fewer than harms.
9. Locked class-1 false-positive removals exceed creations.

## XAI review

The readiness tool exports a common `xai_priority_cases.csv` containing
class-1 false-positive removals, harms, retained false positives, false
negatives, and corrections. Run the same sample indices through keeper and
candidate XAI in FP32. Review Grad-CAM, rollout, raw attention, background
blur/gray, center occlusion, and object desaturation. The audit is rejected if
the precision gain is explained primarily by background suppression or if
candidate evidence breaks true class-1 fruit for a visually consistent reason.

## Promotion boundary

Passing this protocol establishes a two-checkpoint precision deployment
candidate. It does not automatically replace the single-checkpoint training
keeper. Command promotion additionally requires a frozen final-test result,
deployment/export support for both engines plus the decision rule, complete
artifact hashes, and a documented compute-cost tradeoff.

SHA-256 of the passing validation `summary.json`. The apply tool rejects a
